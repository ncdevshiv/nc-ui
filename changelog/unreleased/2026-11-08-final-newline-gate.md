- **Every text file now ends with exactly one newline, and the gate enforces it.** `principle.md` states the rule and claims the staged-content check gates it, but nothing did, and 23 tracked files had no final newline at all. The hygiene scanner checks it in both modes — `--tree` reads each file, `--staged` reads git's own "No newline at end of file" marker — and the files are fixed. The fuzz corpus is excluded: a seed without a trailing newline is a valid fuzzer input, not a malformed document.
