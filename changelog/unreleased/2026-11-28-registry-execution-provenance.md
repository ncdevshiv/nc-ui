- **Registry entries now carry execution provenance, and stale evidence degrades instead of hiding.** Every complete feature may carry `execution` with the instant and machine class where its cited tests last actually ran. The gate's test legs capture cargo's output and `tools/record_execution_provenance.py` stamps exactly the entries whose test targets appear in the log with passing tests — a feature-gated binary that never ran stamps nothing, which is the difference between "tests exist" and "tests ran here". The validator derives an effective status: provenance older than 30 days, malformed, or absent degrades the entry to stale. Degradation is reported beside the platform gaps rather than blocking, because provenance can only be written by a gate that passes and a blocking rule would deadlock its own remedy. `ncui.feature.status` serves the stamped document unchanged, so agents see when and where every claim was last proven. Proven by `a_deliberately_staled_entry_degrades` in the registry validator's own suite.
