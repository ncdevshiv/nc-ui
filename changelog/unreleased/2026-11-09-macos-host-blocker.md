- **The macOS window-host blocker is recorded, with its source.** tao's macOS backend panics — "On macOS, `EventLoop` must be created on the main thread!" — and its `PlatformSpecificEventLoopAttributes` is an empty struct, so unlike Windows and the X11/Wayland targets there is no any-thread switch. This host creates the loop on a worker thread by design, so the release configuration cannot open a window on macOS as it stands, and the host's tests are compiled out there with that reason rather than left to panic in CI's `macos-latest` leg. `docs/known-gaps.md` carries it; making macOS work means giving the engine loop the main thread there, which cannot be verified from this machine.
